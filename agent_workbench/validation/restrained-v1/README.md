# 克制型路由固定验证集 v1

本批用于未来只调整阈值时的产品偏好验证，不是任务难度分类测试。
本次只准备、检查格式及冻结文件，没有运行 100 条路由或请求回答模型。

## 固定内容

- 100 条，简洁、标准、深入各 20 条，预期不注入 40 条。
- 10 类各 10 条，每类 8 条 calibration、2 条 validation。中英文按集合保持相同比例。
- 正向用例表达范围收敛、理解联系、完成核对、检验前提或多因素相互影响；不使用明确档位口令。
- 负向用例覆盖问候、急迫/郑重语气、纯任务主题、引用、代码、格式限制和不明确要求。
- 默认锚点、引导正文、模型文件、解析及判决代码、用例、预期标签和集合划分均记录哈希。
- `cases.md` 便于阅读，`cases.csv` 可用 Excel 打开；`cases.json` 为完整原始用例。
- 标签是预先编写的产品预期，不是客观真理。保留验证集由同一作者准备，不是外部独立盲测。

## 调整范围

仅允许两项全局参数：`min_score` 和 `min_margin`，基线分别为 0.52 和 0.03。
固定 top-k=3、窗口和引用处理、明确规则、默认示例与正文；不加特例，不按单个用例设阈值。

不承诺两项阈值能适配所有用例。阈值只能接受或拒绝现有候选，不能修复错误的排名、材料过滤、否定解析或显式规则。
发生这些情况时记录限制，不通过改标签、删难例或暗改算法来获得高分。

## 未来执行

在仓库根目录运行。每轮使用唯一 run-id，禁止覆盖旧结果。以下只是运行说明，本次没有执行：

```powershell
$env:PYTHONIOENCODING='utf-8'
& agent_workbench/.venv/Scripts/python.exe agent_workbench/validation/restrained-v1/run.py --run-id baseline --split calibration --min-score 0.52 --min-margin 0.03
```

使用实际本地 E5 和生产路由，只通过内存覆盖两个阈值，不改用户配置，不调用回答 API。
这不是前端端到端测试，也不验证回答质量。脚本会拒绝冻结文件发生变化的运行。
日后若将选定阈值写入产品源码，要另行记录发布差异，不能静默更新当前冻结清单。

先用 80 条选择阈值，在选定后才运行 20 条保留验证：

```powershell
& agent_workbench/.venv/Scripts/python.exe agent_workbench/validation/restrained-v1/run.py --run-id final-check --split validation --min-score 0.52 --min-margin 0.03 --confirm-validation
```

不能看完 validation 的错误再不断重调并继续称它为保留验证；这样做以后它也变成了调参集。

## 读结果

分别记录正确、不应注入却注入（false_trigger）、错档（wrong_tier）、应注入未注入（miss）及技术失败。
优先关注误触发和错档，再看漏触发与覆盖率。不命中是允许的，但不能把“全部不命中”包装成成功。
报告同时展示触发精确率、覆盖率、负向误触发数和正向漏触发数，不仅展示一个总分。
技术失败不能因为返回了 null 就算正确不注入。

阈值搜索范围、误触发容忍度等验收标准应在未来调参前确认，不能看到成绩后倒推标准。
本次未自动搜索或选定新阈值，也没有更改当前产品的 0.52 / 0.03。
